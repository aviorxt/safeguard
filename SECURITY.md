# Security policy

For a sensitive vulnerability in the builder, workflows or website, email **dns@avrxt.tech**. Include affected version/commit, impact, minimal safe reproduction and mitigation ideas. Do not send passwords, tokens, private client IDs, malware payloads or personal browsing histories. No response-time guarantee or bug bounty is offered.

Ordinary false positives and missed threat domains belong in the public issue forms, with public evidence and domain names only. Do not publish exploit details or sensitive configuration before maintainers have had an opportunity to investigate.

Contributions from forks run with read-only permissions. Do not use `pull_request_target` to run contributor-controlled code with secrets. Source download failures, suspicious count reductions, invalid syntax and checksum mismatches must stop publication.
