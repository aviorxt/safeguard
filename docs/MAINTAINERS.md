## Updates & verification

| Job | When | What it checks |
| :--- | :--- | :--- |
| [Update Safeguard](https://github.com/aviorxt/safeguard/actions/workflows/update.yml) | Daily **03:17 UTC / 08:47 IST**, manual runs, and builder/input changes | Unit tests, all source downloads, source minimums, a maximum 25% source reduction, strict DNS syntax, deduplication, and site packaging |
| [Validate repository](https://github.com/aviorxt/safeguard/actions/workflows/ci.yml) | Every PR and push to main | Tests, JavaScript syntax, manifest integrity, counts and complete site packaging |
| [Check published blocklists](https://github.com/aviorxt/safeguard/actions/workflows/check.yml) | After successful updates, every six hours, or manually | HTTPS, every download checksum, catalog/report equality with GitHub, and a successful list build within 48 hours |
| Cloudflare Pages | Every main-branch commit | Deploys the verified repository snapshot to **safeguard.avrxt.tech** |

The [build report](https://safeguard.avrxt.tech/blocklists/report.json) contains current counts, source hashes and output hashes. The [deployment record](https://safeguard.avrxt.tech/deployment.json) identifies the deployed commit. The website refreshes its displayed report every five minutes and marks reports over 48 hours old as overdue. This indicator measures report freshness, not a live threat audit.

All downloads must validate before published files are replaced. A failed build preserves the previous publication. Publication checks retry for up to ten attempts, 30 seconds apart, to allow Pages deployments to finish. Failures appear in Actions; email delivery depends on your GitHub notification settings. GitHub schedules can be delayed, and scheduled runs in public repositories may be disabled after prolonged inactivity.

## Sources & transparency

Safeguard is an **AVRXT-maintained aggregation**, built from [HaGeZi DNS Blocklists](https://github.com/hagezi/dns-blocklists) with local overrides. We credit the upstream maintainers and do not claim independent discovery of every domain.

- [sources.json](sources.json): exact upstream URLs, profile mappings and minimum counts.
- [catalog.json](catalog.json): every subscription, grouping, description and restriction notice.
- [sources/](sources/): complete verbatim source snapshots and their upstream notices.
- [rules/block.txt](rules/block.txt): reviewed additional domains, applied to every profile.
- [rules/allow.txt](rules/allow.txt): reviewed exceptions applied to every profile.

The ads/tracking profile uses HaGeZi NORMAL and can also include security domains. Threat Protection uses TIF MINI, which covers several threat types together; we do not invent separate malware/phishing labels for unclassified domains. Smart TV combines the LG webOS and Roku tracking sources.

Allowing a domain removes its descendants. If an exception sits inside a broader blocked parent, the parent rule is also suppressed to keep the generated formats consistent; that can unblock sibling names. Suppressed rules are recorded in the report. Review broad exceptions carefully.

## Contribute, fork & migrate

Forking is welcome. Read [CONTRIBUTING.md](CONTRIBUTING.md), [MIGRATION.md](MIGRATION.md), and the [PR template](.github/pull_request_template.md). Submit a focused branch with a clear before/after description, source attribution, tests and any migration/rollback steps. Main requires a pull request and the **Validate repository** check; force pushes and branch deletion are blocked. Daily generated updates use the dedicated automation-bypass path described in the contribution guide.

Use the [issue chooser](https://github.com/aviorxt/safeguard/issues/new/choose) for false positives, missed threats, category requests, bugs, or migration requests. Include domain names and relevant public evidence; never post passwords, tokens, client IDs, private logs or personal browsing URLs. A report does not automatically change the allowlist.

```bash
python -m unittest discover -s tests
python scripts/build.py
python scripts/build_site.py
python scripts/check_updates.py
```

Python 3.11+ and Node.js are used for validation; the Python build requires only the standard library. `build.py` downloads upstream sources. `build_site.py` is offline and packages the validated files into `dist/`. Cloudflare uses `python scripts/build_site.py`, output directory `dist`, branch `main`. No deployment token, analytics, database or user account is required by the public site.

## Limits & support

DNS filtering cannot inspect encrypted page paths, remove same-domain video ads, enforce Safe Search by itself, or block every threat. Keep DNSSEC, Safe Search, parental classification and Safe Browsing configured separately in your resolver. False positives and missed domains are possible; a matched domain does not prove every page on it is harmful.

Public reports: [GitHub issues](https://github.com/aviorxt/safeguard/issues/new/choose). Private security reports: see [SECURITY.md](SECURITY.md). Contact: **dns@avrxt.tech**.
